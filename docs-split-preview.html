Set Up Local LLM Dialogue for NPCs in Godot 4

Updated 20 Sep 2026 by Alex Moreno 18 min read

Run a small language model on the player's machine, stream replies into a dialogue box, and keep latency low enough to feel like conversation. No server, no per-request cost, and it works offline.

  • Godot 4.4+
  • 8 GB VRAM
  • ~2 GB disk

  • Install the model

Overview

The setup has three parts: a quantized model file shipped next to your game, a LocalLLM node that loads it once at startup, and a dialogue script that streams tokens into your UI as they arrive.

If you've used Godot's signals before, the streaming part will feel familiar. Each token arrives as a signal and you append it to a label.

Install the model

Download a quantized model and place it in res://models/. Anything around 3–4B parameters runs comfortably on mid-range GPUs.

npc_dialogue.gd

extends Node

@onready var llm := $LocalLLM

func ask_npc(prompt: String) -> String:
	# Keep replies short so they fit a dialogue box
	var reply := await llm.generate(prompt, {"max_tokens": 80})
	return reply.strip_edges()

Ship the model as a separate download. Bundling it inflates your export and slows store review.

Pick a model size

Bigger isn't better here. Players notice latency long before they notice a slightly smarter NPC.

Folder layout

  • Keep models in res://models/ and exclude them from the export filter.
  • Put prompt templates in res://dialogue/prompts/ so writers can edit them.
  • Press Ctrl + S after editing a template; the node reloads it on save.

Stream replies

Waiting for the full reply feels slow. Streaming each token as it arrives makes even a 7B model feel responsive.

Players forgave a two-second reply once the text started appearing instantly. Perceived latency is what matters.

Playtest notes, build 0.4

Never block the main thread while generating. Use await or a worker thread, or the game will stutter.

Cache and latency

Cache the system prompt once per NPC. Rebuilding it for every line doubles the time to first token.

Warm the model up with a one-token request during the loading screen. The first real reply will be much faster.

Troubleshooting

If replies cut off mid-sentence, raise max_tokens or ask the model for shorter answers in the system prompt.
